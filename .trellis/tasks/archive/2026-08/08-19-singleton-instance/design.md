# 设计：命名互斥体单例

## 概述

在 `wWinMain` 入口处、**一切副作用发生之前**，用命名互斥体检测是否已有 CClose 实例：

- 已有实例 → 第二个实例静默返回退出。
- 无实例 → 当前实例成为唯一实例，持有互斥体句柄直至进程退出。

采用**会话本地命名空间**（不带 `Global\` 前缀）：同一登录会话内只允许一个实例；不同会话（如多用户 RDP）各自独立，符合托盘常驻工具的定位。

## 边界与职责

- 全部改动在 `src/main.zig`：
  - 常量：`ERROR_ALREADY_EXISTS`、互斥体名称宽字符串。
  - extern：`kernel32::CreateMutexW`、`kernel32::GetLastError`。
  - 全局：`g_singleton_mutex: ?HANDLE`（持有句柄，进程生命周期内有效）。
  - `wWinMain` 顶部：单例检测逻辑。
- `build.zig` / `build.zig.zon`：**不修改**。

## 流程

```
wWinMain 入口（第一行）
  → CreateMutexW(null, FALSE, "CClose_Singleton_Mutex_v1")
  → GetLastError() == ERROR_ALREADY_EXISTS ?
      ├ 是 → return 0（静默退出，无任何窗口/钩子/托盘副作用）
      └ 否 → g_singleton_mutex = 句柄，继续原有初始化
               （SetProcessDPIAware → 注册窗口类 → 创建主窗口 → initTooltip → 消息循环）
进程退出 → 互斥体句柄由内核自动关闭 → 互斥体销毁 → 新实例可立即启动
```

## 关键点

| 项 | 决策 | 理由 |
|---|---|---|
| 检测 API | `CreateMutexW` 命名互斥体 | 同进程可重入、跨进程唯一、内核级互斥；句柄随进程退出自动释放，天然满足"旧实例退出后可重启" |
| 命名空间 | 不带前缀（会话本地） | 每登录会话一个实例即可；无需跨会话全局互斥（避免多用户 RDP 场景互相阻塞） |
| 名字稳定性 | 固定字符串 `CClose_Singleton_Mutex_v1` | 应用唯一绑定、跨启动稳定 |
| 检测时机 | `wWinMain` 第一行，`SetProcessDPIAware` 之前 | 第二个实例不产生任何副作用（不建窗口/钩子/托盘/类） |
| 失败容错 | `CreateMutexW` 返回 null 且非 ALREADY_EXISTS → 继续运行 | 互斥体创建失败极罕见；托盘工具宁可无单例保护也不应完全无法启动 |
| 句柄持有 | 存全局 `g_singleton_mutex` | 明确持有直到进程退出；Zig 无 GC，主要为可读性与防优化误删 |
| 退出码 | 第二个实例 `return 0` | 干净退出，调用方无需特殊处理 |

## 并发/边界

- **同时启动两个实例**：两个 `CreateMutexW` 同一名字，内核保证只有一个实例拿到"新建"语义，另一个得到 `ERROR_ALREADY_EXISTS`。无竞态。
- **旧实例崩溃**：进程终止即关闭句柄，互斥体释放，无残留锁。
- **管理员/普通权限混合**：同为交互会话进程，会话内命名对象可见，检测正常。
- **与托盘/钩子交互**：单例检测完全不触碰这些子系统，纯入口处守卫。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 互斥体名字与其它程序撞名 | 名字含 `CClose` 专属标识，撞名概率极低；撞名后果仅为误判重复（保守可接受） |
| 误杀（第一实例本应运行却被判重复） | 只有真存在同名互斥体才 `ERROR_ALREADY_EXISTS`，误判需另一程序恰好使用同名互斥体 |
| 多会话各跑一个实例 | 设计上接受（会话本地语义），非缺陷 |
