# 单例功能：避免 CClose 多实例运行

## Goal

确保同一时刻只有一个 CClose 实例在运行。当用户再次启动 CClose 时，第二个实例检测到已有实例后**静默退出**，已有的第一个实例继续运行。

## Background

当前 CClose 没有单例保护。多开时每个实例都会：安装低级鼠标/键盘钩子（`WH_MOUSE_LL`/`WH_KEYBOARD_LL`）、创建托盘图标、注册窗口类。这会导致：
- 多个钩子同时处理同一输入，置顶/关闭等动作被重复触发或冲突；
- 托盘出现多个图标；
- 重复注册窗口类（已存在的类被 `RegisterClassExW` 忽略，但整体状态混乱）。

CClose 是一个托盘常驻工具，无可见主窗口。

## Requirements

1. 使用**命名互斥体**（`CreateMutexW`）实现单例检测。
2. 第二个实例检测到已有实例时**静默退出**（无弹窗、无托盘图标、不安装钩子），返回码可忽略。
3. 第一个实例正常运行，行为完全不变。
4. 旧实例正常退出后，新实例应能立即正常启动（互斥体句柄随进程退出自动释放，无残留锁）。
5. 单例检测须在**创建窗口、安装钩子、添加托盘图标之前**完成，避免第二个实例产生任何副作用。
6. 保持自包含：仅用 Win32 原生 API（`kernel32`），不引入第三方依赖，不改 `build.zig` / `build.zig.zon`。
7. 互斥体名须稳定且与该应用唯一绑定，避免与其它程序冲突。

## Non-Goals

- 不做"旧实例退出、新实例接管"的替换式单例。
- 不做"第二实例唤起/闪烁已有实例托盘图标"。
- 不提供配置开关（单例始终开启）。
- 不改变钩子、托盘、置顶等既有逻辑。

## Acceptance Criteria

- [ ] 启动第一个实例后，再启动第二个实例，第二个立即退出；第一个实例保持运行、功能正常。
- [ ] 第二个实例退出时不创建托盘图标、不安装钩子、不注册窗口类（无任何可见副作用）。
- [ ] 退出第一个实例后，再启动新实例可正常运行（互斥体无残留）。
- [ ] `zig build` 编译通过。
- [ ] 既有功能（置顶提示气泡、中键关闭、右键最小化、双击 Esc、托盘菜单）不回归。

## Notes

- 实现集中在 `src/main.zig`（`wWinMain` 入口处新增互斥体检测 + 常量 + extern）。
- 技术方案见 `design.md`，执行清单见 `implement.md`。
